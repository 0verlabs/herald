The Private Inference Gateway gives you LLM inference on [0G Private Compute](https://pc.0g.ai), paid per request. No account, no API key. Your wallet signs a USDC payment for each call over the [direct rail](/pages/product/rails/direct).

Inference runs inside trusted execution environments and responses are attested. The model list and account tooling live at [pc.0g.ai](https://pc.0g.ai).

The gateway lives at:

```text
https://gateway.heraldprotocol.xyz
```

## Endpoints

The gateway serves the full [0G Private Compute API](https://router-api.0g.ai). Two endpoints are payment gated:

| Endpoint                    | Format                  |
| --------------------------- | ----------------------- |
| `POST /v1/chat/completions` | OpenAI chat completions |
| `POST /v1/messages`         | Anthropic messages      |

## Payment

A request without payment returns `402 Payment Required` with a `payment-required` header describing what the gateway accepts: the network, USDC as the asset, the recipient, and a maximum amount. Your client signs a payment and retries. With the `upto` scheme you authorize a maximum, and the gateway settles only what the request actually cost based on token usage.

You can pay from 0G, Base, or Arbitrum. Monad, BNB Smart Chain, Solana, and Stellar are coming. See [supported chains](/pages/product/rails/direct#supported-chains).

The facilitator sponsors gas for the Permit2 approval, so your wallet only needs USDC.

## Quickstart

The full working client example is at [0verlabs/herald-gateway-example](https://github.com/0verlabs/herald-gateway-example), built with Bun.

<Steps>
  <Step title="Install dependencies">
    You need a wallet with USDC.

    ```sh
    npm install @x402/core @x402/evm @x402/fetch viem
    ```

  </Step>
  <Step title="Set your private key">
    Put a wallet private key in `.env`:

    ```text .env
    EVM_PRIVATE_KEY=0x...
    ```

  </Step>
  <Step title="Wrap fetch and call the gateway">
    ```typescript index.ts
    import { x402Client } from "@x402/core/client";
    import { toClientEvmSigner } from "@x402/evm";
    import { UptoEvmScheme } from "@x402/evm/upto/client";
    import { wrapFetchWithPayment } from "@x402/fetch";
    import { createPublicClient, http } from "viem";
    import { privateKeyToAccount } from "viem/accounts";
    import { base } from "viem/chains";

    // Create signer
    const signer = privateKeyToAccount(
      process.env.EVM_PRIVATE_KEY as `0x${string}`,
    );

    const publicClient = createPublicClient({
      chain: base,
      transport: http(),
    });

    const evmSigner = toClientEvmSigner(signer, publicClient);

    // Create x402 client and register EVM scheme
    const client = new x402Client();
    client.setSpendControls(false); // set your spend controls, false to disable
    client.register("eip155:8453", new UptoEvmScheme(evmSigner));

    // Wrap fetch with payment handling
    const fetchWithPayment = wrapFetchWithPayment(fetch, client);

    // Make request - payment is handled automatically
    const response = await fetchWithPayment(
      "https://gateway.heraldprotocol.xyz/v1/chat/completions",
      {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
        },
        body: JSON.stringify({
          model: "glm-5.3-flash",
          messages: [{ role: "user", content: "Hello!" }],
          stream: true,
        }),
      },
    );

    const data = await response.text();
    console.log("Response:", data);
    ```

    This example registers a scheme for Base (`eip155:8453`). To pay from another chain, register a scheme for that chain ID with `client.register(...)`.

  </Step>
  <Step title="Run">
    ```sh
    bun run src/index.ts
    ```

    The first 402 round trip happens behind `wrapFetchWithPayment`. Your code only sees the final response.

  </Step>
</Steps>
